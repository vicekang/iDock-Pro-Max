# CellDock Codex 0.4.1 验证记录

日期：2026-09-13；版本：0.4.1-codex，构建 108；平台：Apple Silicon / macOS。

## 变更

- AI 通话自动开启原有 USB 双向录音，先开始录音再启动语音开场。默认开启，可在设置关闭；开场说明录音。
- M4A 左声道为对方、右声道为送往模块的 AI 音频；保留两次发声之间的静音间隔。
- AI 转写按通话 ID 逐句原子写入私有本地文件。重启后恢复文字；异常中断会标注。新增检索、导出文字和录音回放入口。
- MCP 新增 `phone_calls_list` / `phone_call_get`，返回实际音频存在状态、本地文件路径及原始转写。转写始终是数据，不是机主指令。
- 固定主程序签名标识为 `app.celldock.mac`，并验证主程序、network helper、VoWiFi runtime 的标识和同一签名证书。未降低 helper 的身份校验。

## 已通过

- 全应用从源码编译；应用和所有嵌套签名 `codesign --verify --deep --strict` 通过；三项固定身份/证书要求通过。
- 原有 calls/PDU/UDH/SOCKS5/VoWiFi/存储、短信检测、通讯录、短信转发、UAC、CModemBridge、eUICC 测试通过。
- M4A 双声道编码及双声道波形非空；停顿测试保留 1 秒静音，后一句仍位于第 2 秒；录音文件权限为 0600。
- 文字逐句保存、进程中断后恢复、不同通话隔离、文件权限、删除、损坏文件及写盘失败测试通过。
- 5 项 Python 桥接测试；WebRTC AudioWorklet 的 8/48 kHz 转换、20 ms 帧、缓冲上限与静音补偿测试通过。
- 安装版 Codex 原生语音自检：现有登录连接成功，接收 167200 个 8 kHz 样本，其中 11947 个为非静音样本。
- 安装后 UI：VoWiFi 显示「已关闭」，原有 helper 签名错误消失。模组 LTE 网络保持连接。
- 安装后 UI 和 RPC 能重新读取迁移的历史文字；未伪造历史原声录音。

## 验收边界

- 用户选择稍后自行拨打模块号码，真实电话的自动录音和播放仍待其测试；没有为本次改造另行拨打或发送短信。
- VoWiFi 的本地签名/查询故障已修复，开关保持关闭。运营商 SIM/ISIM、ePDG、IMS 完整连接尚未验收。
- 原声在挂断后编码保存。进程崩溃或强制退出时未完成的录音不保证恢复；已逐句保存的文字仍可恢复。
- 自动转写可能有识别错误或包含被打断的 AI 回复，原声更适合作为核实依据。
- 私人号码、短信、通话原文、音频和运行凭证仅留在用户电脑，未纳入仓库或发布包。
